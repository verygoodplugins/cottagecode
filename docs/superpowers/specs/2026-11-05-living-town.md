# Living town and workbenches

Jack's refinement on 2026-11-05: high information density and an attractive, living town should coexist. The town needs a heartbeat, with easy project focus and activity visible through its environment. This supersedes the earlier full-surface Dispatch/Threads replacement and suspended-walking choice.

The original town remains mounted, visible and walkable while Dispatch or Threads opens as a workbench below it. A continuous balance control allocates 30–75% of the shared space to scenery and changes immediately on input. Its DOM node lives outside streamed markup. Escape closes the workbench; selecting a cottage uses the shared evidence drawer. Keyboard movement belongs to the focused canvas.

The neighbourhood rail summarizes current working, attention and unique ready-PR counts. Choosing a project scopes the ledger and frames all its visible cottages, including resting cottages, without moving plots. When the selected evidence belongs elsewhere, the drawer opens a relevant cottage in the chosen project. All towns restores the wider scope. Ordinary data updates do not reposition the camera.

The environmental language is grounded:

- Moving ground dashes mark reported working cottages that are neither stale nor explicitly quiet. Amber lanterns mark attention. These are aggregate signals, not claims of measured throughput.
- Potting benches, loading depots and tiny gardeners/craftsfolk are decorative village inhabitants. Their pace follows the district's working count; they are not additional agents or inferred professions. Resting is allowed.
- A newly observed canonical merged PR creates one labeled cart with one parcel. The parcel means that PR's changes. It does not represent a commit count, file count, deployment or release. Shared PRs count once.
- A newly observed closed PR creates an empty cart travelling home. No agent is fired or removed by the animation. Actual occupancy remains feed-owned.
- Carts run only at the recorded household, never an unrelated cottage. Initial inventories do not generate parades; source changes immediately clear traffic. Lifetimes and remembered identities are bounded. Stale feeds and reduced-motion preferences stop the new movement.

The field guide explains these meanings and the basic interactions without a first-run modal. Sound and music retain their independent, off-by-default lifecycle. Real messages still require explicit Send through the existing guarded route.

Validation for this iteration includes controller checks for volume/time, workbench balance input/change/keyboard behavior, PR identity and shipment direction, unavailable households, source resets, unique counts and stable project bounds. Browser acceptance covers the live preview, simultaneous town/workbench, repo focus, desktop and narrow layouts, all three perspectives, range controls and lighting. Private live screenshots stay outside the repository.

This pass establishes the rhythm. Richer crafts, mining, road building, material inventories or workload stress are future vocabulary; they are not fabricated from task titles or missing telemetry.
